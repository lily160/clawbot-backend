# 体检报告模块功能说明

> 该文档聚焦 `modules/health/report`，描述当前代码已经实现的 PDF 体检报告解析流程、输出内容和数据流。

## 1. 模块目标

体检报告模块的目标是：

- 自动解析体检 PDF
- 识别关键指标
- 标注偏高、偏低、异常、正常和未知
- 支持扫描件 OCR 兜底
- 支持历史报告趋势对比
- 生成适合微信阅读的摘要与 Word 文档

模块只做“整理和提示”，不做诊断。

---

## 2. 核心链路

```text
用户上传 PDF
→ HealthReportParseTool
→ HealthReportParseService
→ PdfReportExtractor 提取原生文本
→ 扫描页进入 OCR 兜底
→ HealthIndicatorParser 识别指标与状态
→ ReportTrendAnalyzer 做历史对比
→ ReportSafetyFormatter 生成安全摘要
→ ReportWordExporter 导出 Word
```

---

## 3. 文件与类职责

### 3.1 API 层

#### `HealthReportParseTool`

文件：`bot/src/main/java/com/github/wechat/cloudbot/modules/health/report/api/HealthReportParseTool.java`

职责：

- 作为 Function Calling 工具入口
- 接收本地 PDF 路径
- 校验文件是否存在、是否为 PDF
- 调用解析服务
- 若用户有历史报告，补充趋势分析、复查建议和跟进计划
- 返回 JSON 文本结果

### 3.2 Service 层

#### `HealthReportParseService`

职责：

- 编排 PDF 文本提取与 OCR
- 调用指标解析器
- 生成 `HealthReportParseResult`

#### `ReportTrendAnalyzer`

职责：

- 对比当前报告与历史报告
- 生成趋势项
- 生成分级复查建议
- 生成异常跟进计划

#### `ReportSafetyFormatter`

职责：

- 将结构化结果格式化成适合微信展示的安全文本
- 控制医疗措辞，避免输出诊断性语言

#### `ReportWordExporter`

职责：

- 将结构化结果导出为 Word 文档
- 包含摘要、异常项、趋势、建议和免责声明

### 3.3 Infra 层

#### `PdfReportExtractor`

职责：

- 使用 PDFBox 提取原生文本
- 对文本过少的页面标记为 OCR_REQUIRED
- 提供单页渲染为图片的能力

#### `AliyunOcrClient`

职责：

- 调用阿里云 OCR
- 支持 AppCode 与 AccessKey 两种方式
- 返回页面文字内容

## 4. 解析策略

### 4.1 原生文本优先

如果 PDF 本身带文本层，则优先用原生文本解析。

优势：

- 速度快
- 精度高
- 不依赖 OCR 配置

### 4.2 扫描页 OCR 兜底

如果某页原生文本太少，会判定为需要 OCR，再将该页渲染成图片交给 OCR 服务。

### 4.3 指标识别

模块会从文本中识别：

- 数值型指标
- 定性型指标
- 带参考范围的项目
- 箭头符号、偏高偏低提示
- 不同参考范围分隔符

### 4.4 状态判断

指标状态一般分为：

- `NORMAL`
- `HIGH`
- `LOW`
- `ABNORMAL`
- `UNKNOWN`

---

## 5. 历史趋势与复查建议

如果用户上传过历史报告，模块会：

- 对比当前与上一次指标
- 识别“好转”“改善”“加重”“新增异常”
- 为异常项生成科室建议和复查建议
- 给出复查时间建议和行动项

趋势分析与建议主要由 `ReportTrendAnalyzer` 完成。

---

## 6. 对外输出

### 6.1 文字摘要

摘要内容通常包括：

- 总页数
- 识别到的指标数量
- 偏离参考范围的数量
- 是否有缺少参考范围的项目
- 是否存在历史趋势
- 是否建议设置复查提醒

### 6.2 JSON 结构结果

`HealthReportParseTool` 的返回值通常会包含：

- `message`
- `result`
- `trends`
- `followUpSuggestions`
- `followUpPlans`
- `hasHistory`

### 6.3 Word 文档

如果由编排层触发文件发送，系统会输出 Word 解析报告，适合保存和复查时查看。

## 7. 配置要求

### 7.1 OCR 可选配置

可选使用阿里云 OCR：

```yaml
health:
  report:
    aliyun-ocr:
      app-code: ${ALIYUN_OCR_APPCODE:}
      access-key-id: ${ALIYUN_OCR_ACCESS_KEY_ID:}
      access-key-secret: ${ALIYUN_OCR_ACCESS_KEY_SECRET:}
      endpoint: https://ocr-api.cn-hangzhou.aliyuncs.com
```

### 7.2 本地模板

本地配置模板在：

- `bot/src/main/resources/application-local.yml.example`

---

## 8. 当前行为边界

- 只接受本地 PDF 路径
- 不处理远程 URL
- 不提供医学诊断
- 不把异常值解释成最终结论
- PDF 过大、损坏、加密或无文本时会直接报错或回退

---

## 9. 调试建议

如果解析结果不理想，可以依次检查：

1. PDF 是否带文本层
2. OCR 是否配置
3. 指标格式是否符合常见体检文本习惯
4. 文本是否被表格、换行或扫描噪声打断
5. 历史报告是否成功存储，趋势分析是否可用
