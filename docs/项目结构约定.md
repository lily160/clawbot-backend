# 项目结构约定

> 本仓库是 **微信 Agent**。采用折中结构：
> **外层按能力模块划分，模块内再按 api / service / infra 薄分**；
> 平台能力（通道、编排、持久、共享模型）放在 `platform`。
> 借鉴阿里手册的职责分离，不照搬 COLA。

---

## 1. 总览

```
bootstrap                 启动入口（扫描整个 com.github.wechat.cloudbot）
platform                  跨能力平台：通道 / Agent 编排 / 插件 SPI / 模型 / 持久 / 公共配置
  ├── agent/               AgentOrchestrator、ToolRegistry、AgentTool 契约
  │   └── spi/             ToolPluginProvider / PluginScanner / PluginClassLoader
  ├── channel/wechat/       收发、扫码、ILink 装配
  ├── model/               ChatMessage、LlmTurn
  ├── persistence/         AuthStorage、ChatMemoryRepository
  └── config/              CloudbotProperties 等

modules.*                 能力模块
  └── api|service|infra   每模块三层
```

运行时链路：

```
微信
 → platform.channel
 → platform.agent（合并 + 编排 + ToolRegistry 路由）
 → modules.*.api（Facade / AgentTool）
 → modules.*.service → modules.*.infra
 → platform.persistence
 → platform.channel 回发
```

依赖规则：

- `modules` → `platform`（允许）
- `modules` 之间 **禁止** 互摸对方 `infra`；跨能力只经 `platform.agent` 或对方 `api`
- 模块内：`api` ← `service` ← `infra`

### 模块内三层

| 内层 | 放什么 |
|------|--------|
| **api** | 给编排/其他模块的入口：Facade、`AgentTool`、Gateway 接口 |
| **service** | 本能力业务规则 |
| **infra** | HTTP / SDK / Properties / RestClient Bean（数据库数据源） |
| **repository** | 仅数据密集模块需新增此层，放 SQLite/DB 操作（如 `inspiration` 模块） |
| **model** | 仅持久化模块需新增此层，放实体/DTO（如 `inspiration` 模块） |

## 3. 协作约定

- 包根固定：`com.github.wechat.cloudbot`
- Java 21 / Spring Boot 3.3.x / wechat-ilink-sdk 2.3.3（Maven 依赖，非本仓库源码模块）
- 分支：`feat/chat-…`、`feat/search-…`、`feat/agent-…`、`feat/persistence-jdbc-…`
- 一 PR 尽量只动一个 `modules.*` 或 `platform` 的一块
- 新能力 = 新 `modules/<name>/{api,service,infra}` + 在编排中注册
- 新 Tool = 实现 `platform.agent.AgentTool`，放在对应模块 `api`，由 `ToolRegistry` 自动收集
- 数据密集模块可增加 `repository/` 和 `model/` 层（如 `inspiration`）
- 密钥：环境变量或 `application-local.yml`（gitignore）
- 禁止提交：`target/`、`logs/`、`data/`、`cloudbot.db`、真实 key、登录二维码

### 插件系统（SPI）

- 插件 JAR 实现 `ToolPluginProvider` 接口，注册到 `META-INF/services/`
- 放在仓库根 `plugins/` 目录，启动时 `PluginScanner` 自动扫描
- 运行时通过 `/tool reload` 热加载
- 每个 JAR 独立 ClassLoader，与宿主 ClassLoader 隔离
- 插件可实现 `PluginContextAware` 接口获得沙箱 API

## 4. 后续演进

### 数据库

已落地 SQLite 方案（`inspiration` 模块），数据库文件 `cloudbot.db`。
`SqliteDataSource` 负责初始化。后续可扩展 `platform.persistence` 的 JDBC 版。

### Function Calling

编排已落地 Agent Loop：`tool_calls` → `ToolRegistry.execute` → `role=tool` 回灌 LLM；  
tools 定义由 `ToolRegistry.definitions()` 提供。生图/生视频为异步出站旁路，不把媒体字节回灌模型。

### 插件 SPI

已落地热加载插件系统，支持：
- 启动时自动扫描 `plugins/` 目录
- 运行时 `/tool reload` 热加载
- 独立 ClassLoader 隔离
- 工具注册/注销/启用/禁用
