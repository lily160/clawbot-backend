# 健康管家功能说明

> 适用范围：微信 Cloudbot 中的 `modules/health/**` 能力集合。
>
> 本文以当前代码实现为准，描述已经落地的健康管家能力、运行方式、边界约束与交互方式。

## 1. 项目定位

健康管家是 Cloudbot 的一组面向家庭健康管理的功能模块，目标不是替代医生，而是帮助用户在微信里完成以下高频事情：

- 建立和维护健康档案
- 根据症状做导诊和挂号建议
- 解析体检 PDF，输出结构化摘要和复查建议
- 记录、查询和维护用药信息
- 设置吃药、喝水、运动、早睡、复查等提醒
- 记录健康打卡
- 输出体检模板，便于咨询与沟通

所有健康相关回复都遵循统一免责声明：

> 仅供参考，不能替代执业医师诊疗。如有不适请及时线下就医。

## 2. 当前功能总览

### 2.1 健康档案

支持用户为本人或家人建立健康档案，并在后续导诊、挂号、体检建议中自动复用。

- 建档工具：`health_profile_upsert`
- 查询工具：`health_profile_get`
- 关键字段：关系、姓名、性别、出生年份、过敏史、慢病史
- 交互特点：首次录入通常会先暂存，再由用户确认后生效

### 2.2 症状导诊

根据用户描述的症状，返回建议科室、常见检查项目、追问问题和免责声明。

- 工具名：`health_triage_department`
- 支持多轮追问
- 支持复诊场景的“和上次一样吗”识别
- 支持对历史对话进行症状累积，减少重复追问
- 与 `TriageService`、`HealthCommandRouter` 协同工作

### 2.3 挂号推荐

根据导诊结果返回医院候选与预约入口，优先给出可操作的挂号建议。

- 推荐接口：`health_booking_recommend`
- 确认接口：`health_booking_confirm`
- 当前实现支持真实平台适配器与兜底候选号源
- 如果真实挂号客户端未接入，不会伪造“已成功预约”回执

### 2.4 体检报告解析

用户上传 PDF 体检报告后，系统自动抽取文本、识别指标、标记偏高/偏低/异常，并输出趋势与复查建议。

- 工具名：`health_report_parse`
- PDF 原生文本优先，扫描页走 OCR 兜底
- 支持历史报告对比
- 可生成 Word 文档摘要

### 2.5 用药管理

支持药品记录、查看、修改、删除以及与提醒联动。

- 新增用药：`health_med_add`
- 查看用药：`health_med_list`
- 修改用药：`health_med_update`
- 删除用药：`health_med_delete`
- 统计与冲突提示：`health_med_stats`、`health_med_otc_check`

### 2.6 健康打卡

支持喝水、运动、早睡等健康习惯打卡，并可联动提醒列表。

- 打卡记录：`health_checkin_add`
- 打卡汇总：`health_checkin_today`

### 2.7 日常提醒

支持吃药、喝水、运动、早睡、复查等提醒设置。

- 提醒工具：`health_daily_reminder`
- 同时兼容任务模块的提醒增删查能力

### 2.8 体检模板

输出面向不同人群的体检套餐模板，帮助用户和家属沟通体检需求。

- 工具名：`health_checkup_plan`

## 3. 核心流程

### 3.1 症状导诊流程

```text
用户输入症状
→ HealthCommandRouter / TriageDepartmentTool
→ TriageService 匹配科室与检查项目
→ 必要时追问补充信息
→ 返回建议科室 + 常见检查 + 免责声明
```

### 3.2 挂号推荐流程

```text
导诊结果
→ BookingService 生成医院候选或真实号源
→ 返回 Top 候选与预约入口
→ 用户确认后调用 confirm
→ 返回回执或预约入口说明
```

### 3.3 体检报告流程

```text
用户上传 PDF
→ PDF 文本提取
→ 扫描页 OCR 兜底
→ 指标解析与偏离判断
→ 趋势对比与复查建议
→ 文字摘要 + Word 文档输出
```

### 3.4 用药与提醒流程

```text
用户说“记药 / 查药 / 改药 / 删药 / 设置提醒”
→ 对应 Tool
→ 持久化到数据库或提醒系统
→ 返回确认与免责声明
```

## 4. 共享契约与边界

健康模块的共享对象放在 `modules/health/common`，用于跨子模块协作：

- `PatientRef`
- `TriageResult`
- `SlotOption`
- `BookingReceipt`
- `HealthFlowRequest`
- `HealthFlowSnapshot`
- `HealthFlowResult`
- `HealthFlowAction`
- `HealthDisclaimers`
- `HealthToolNames`

### 4.1 设计约束

- 跨模块只传不可变 DTO
- 不在模块之间直接共享实体、Mapper、ToolCall 或原始 LLM JSON
- 所有医疗回复必须附带免责声明
- 不能输出确诊、处方、改剂量或替代医生结论

## 5. 子模块说明

### 5.1 `modules/health/profile`

职责：

- 录入健康档案
- 查询健康档案
- 为其他健康流程提供档案信息

主要入口：

- `api/HealthProfileUpsertTool`
- `api/HealthProfileGetTool`
- `api/ProfileServicePort`
- `service/ProfileService`

### 5.2 `modules/health/triage`

职责：

- 症状导诊
- 分科目录匹配
- 多轮追问与历史上下文处理

主要入口：

- `api/TriageDepartmentTool`
- `service/TriageService`

### 5.3 `modules/health/booking`

职责：

- 医院候选推荐
- 号源排序
- 预约确认与回执

主要入口：

- `api/BookingServicePort`
- `service/BookingService`
- `infra/BookingQueryClient`

### 5.4 `modules/health/report`

职责：

- PDF 体检报告解析
- OCR 兜底
- 指标识别与趋势分析
- Word 输出

主要入口：

- `api/HealthReportParseTool`
- `service/HealthReportParseService`
- `service/ReportTrendAnalyzer`
- `infra/PdfReportExtractor`
- `infra/AliyunOcrClient`

### 5.5 `modules/health/medication`

职责：

- 用药记录维护
- OTC 风险提示
- 用药提醒联动

主要入口：

- `api/HealthMedAddTool`
- `api/HealthMedListTool`
- `api/HealthMedEditTool`
- `api/HealthMedDeleteTool`
- `api/HealthMedStatsTool`
- `api/HealthMedOtcCheckTool`
- `api/HealthDailyReminderTool`

### 5.6 `modules/health/checkin`

职责：

- 健康打卡
- 打卡统计
- 与提醒联动

主要入口：

- `api/HealthCheckinAddTool`
- `api/HealthCheckinTodayTool`

### 5.7 `modules/health/checkup`

职责：

- 体检套餐模板
- 年龄、性别、慢病史和生活方式建议

主要入口：

- `api/HealthCheckupPlanTool`

## 6. 运行与配置

### 6.1 运行依赖

健康管家相关能力会复用以下外部服务或配置：

- `DEEPSEEK_API_KEY`：对话和润色
- `DASHSCOPE_API_KEY`：视觉、语音相关能力
- `AMAP_API_KEY`：天气/地理能力（健康模块间接复用）
- `ALIYUN_OCR_APPCODE` 或 `ALIYUN_OCR_ACCESS_KEY_ID` / `ALIYUN_OCR_ACCESS_KEY_SECRET`：体检报告 OCR
- 数据库：MySQL / Flyway 迁移

### 6.2 本地配置

建议复制模板：

```powershell
copy bot\src\main\resources\application-local.yml.example bot\src\main\resources\application-local.yml
```

健康报告 OCR 配置示例请参考：

```yaml
health:
  report:
    aliyun-ocr:
      app-code: xxx
      access-key-id: xxx
      access-key-secret: xxx
      endpoint: https://ocr-api.cn-hangzhou.aliyuncs.com
```

## 7. 典型对话示例

### 7.1 建档

```text
用户：帮我给妈妈建档，妈妈对青霉素过敏，有高血压
Bot：先帮你整理一下信息，请确认后保存……
```

### 7.2 导诊

```text
用户：我咳嗽三天还有点低烧
Bot：建议呼吸内科 / 全科，并给出常见检查和追问问题
```

### 7.3 体检报告

```text
用户：[发送 PDF 体检报告]
Bot：输出结构化摘要、异常项、趋势变化和复查建议
```

### 7.4 用药

```text
用户：帮我记下阿司匹林肠溶片，每天一次
Bot：已记录并设置提醒，同时给出风险提示
```

## 8. 合规说明

健康管家模块只做以下事情：

- 信息整理
- 规则匹配
- 风险提示
- 复查建议
- 科室与流程指引

不做以下事情：

- 确诊
- 改处方
- 推荐具体药量
- 替代医生结论
- 伪造医院预约成功回执
